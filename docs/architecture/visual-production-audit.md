# Visual production audit (post-PR #420 baseline)

## Runtime graph and ownership

The production entry point registers one `LevelScene`, which delegates spatial setup to
`LevelRuntime` and the single `TiledWorldBuilder`. Matter owns every body. Tiled owns
bounds, collision, sensors, stairs, spawns, objectives, checkpoints, pickups and exits.
`UIScene` is the sole HUD scene. Before this milestone the builder only consumed the
gameplay layers; every visual object layer was present but empty and therefore ignored.

| Concern | Baseline renderer / owner | Baseline finding |
|---|---|---|
| Background | none (`runtimeBackgroundPath` was empty) | all canonical maps rendered empty space |
| Architecture / props / foreground | none | layers existed but contained zero objects |
| Lighting | none | `LightingAnchors` existed but was empty; no runtime lighting owner |
| HUD | `UIScene` | one placeholder text label, no duplicated HUD |
| Camera | `TiledWorldBuilder` + `LevelRuntime` | Tiled bounds and follow existed; map zoom/rounding were unused |
| Assets | `AssetPreloadScene`, `TiledAssetResolver` | menu, character sheet, campaign/story JSON global; optional single background per level |

## Asset inventory and references

The protected raster files and photographs remain byte-for-byte inputs, not edit
targets. Existing, text-authored institutional SVG scenery under
`assets/visual-v2/environments/institutional` is the only sufficiently broad scenery
set available for Tiled composition. The milestone indexes only the subset actually
referenced by maps; the legacy folder name is an asset location, not a second renderer.
The character sheet is globally loaded and used by menu/character presentation. The
menu image is globally loaded and used by the menu. Protected photographs are currently
editor references: every `BackgroundReference` is invisible and marked `editorOnly`.

Protected-but-not-yet-rendered content includes several real photographs and most
campaign JSON. They remain available to narrative wrappers and future art passes.
No binary is a cleanup candidate.

## Map baseline

All 13 real TMJ maps had identical empty visual-layer structure:
`Background`, `RearArchitecture`, `Architecture`, `RearProps`, `GameplayDecor`,
`FrontProps`, `Foreground`, and `LightingAnchors`. Each did have a distinct gameplay
layout, entry, objective and exit. The empty visual layers made every canonical level
appear equally blank despite correct location/floor metadata. `BackgroundReference`
held a photograph path, but was invisible and intended for the editor only.

The three detailed targets are comedor, pasillos and the Planta Baja hall. Remaining
maps receive deliberately limited, map-specific contextual compositions rather than a
campaign-wide art reconstruction.

## Duplication, dead code and placeholders

The reachable runtime has one world builder and no parallel renderer. Historical
`visual-v2` in asset paths is static content only; there is no reachable Visual V2
system. The reachability/dead-code audits identify no safe additional runtime deletion
for this milestone. Empty visual layers, empty `runtimeBackgroundPath`, generic
`campaign-default` music profiles, numeric floor placeholders (`Piso canónico N`) and
minimal HUD text were presentation placeholders. Spatial gameplay data is active and
must not be removed.

## Gaps that existing assets cannot close

Existing scenery covers institutional corridors, counters, signs, tables, columns,
windows, damage, pipes and debris. It does not provide unique kitchen appliances,
campaign-specific exterior vehicles, bespoke reception furniture, animated rain,
high-resolution wet materials, unique weapon attachments, casings, or complete ally
and zombie animation sets. Runtime light/fog/reflection primitives can add atmosphere,
but cannot legitimately substitute for those missing architectural or prop assets.
No new binary or SVG art is generated by this milestone.
